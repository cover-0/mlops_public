# lecture 폴더 작성 원칙

`lecture/`는 학부 강의자료를 두는 공간이다. 상세 참고 원고(`lecture/docs/`)는 2026-09-13부터 이 저장소에 두지 않고 비공개 저장소에만 유지한다.

**핵심 원칙 한 문장: 압축이 아니라 선별이다.** 상세 참고 원고의 절을 하나씩 대응시켜 줄이면 어려운 내용이 그대로 따라 들어온다. 한 장에서 다룰 핵심 개념을 3-4개만 고르고, 고른 개념은 상세 원고보다 오히려 더 천천히 설명한다. 고르지 않은 내용은 "더 알아보기"에서 `practice/chapter{N}/`의 확장 실습이나 외부 원문으로 가리킨다.

> 이 문서는 `AGENTS.md` §9와 짝을 이룬다. `AGENTS.md` §2(강의 교재 모드 고정 템플릿)와 §2.4(구체성·최신성 규칙, 400줄 하한)는 `docs/` 전용이며 `lecture/`에는 적용하지 않는다.

## 대상 독자와 강의계획서

**`syllabus.md`는 그대로 유지한다.** 수강 대상(3~4학년), 선수 지식, 주차 배정, 실습 구성을 이 규정 때문에 바꾸지 않는다. 바뀌는 것은 강의자료의 **서술 깊이와 담는 분량**이다.

- 강의계획서상 수강 대상은 공공정책·빅데이터·정보시스템 전공 **3~4학년**이다.
- 다만 서술은 **2-3학년이 따라올 수 있는 깊이**로 맞춘다. 수강생을 줄이는 것이 아니라, 쉽게 쓰고 적게 담아 핵심을 확실히 이해시키는 것이 목표다.
- 조직에서 예산을 편성하거나 발주 문서를 검수해 본 경험은 없다고 본다. 조직 운영 절차를 전제한 설명은 이 독자에게 닿지 않는다.
- 목표는 "많이 아는 것"이 아니라 **핵심 개념 3-4개를 자기 말로 설명하고 실습에서 눈으로 확인하는 것**이다.

## 실습은 이론과 맞춘다

**이론과 실습은 서로 가리켜야 한다.** 이론에서 고른 핵심 개념 3-4개가 실습에서 눈으로 확인되고, 실습이 보여 주는 것은 이론에 설명이 있어야 한다.

- 실습 절이 여러 개면, 이론의 핵심 개념과 이어지는 것만 본문에 남긴다.
- 이론 어디에도 근거가 없는 실습 단계·산출물 설명은 본문에서 뺀다. 뺀 것은 “더 알아보기”에 `practice/chapter{N}/` 경로로 남긴다.
- 반대로 실습은 보여 주는데 이론에 설명이 없는 개념이 있으면, 그 개념을 핵심 개념 절에 넣는다. 설명 없는 실습을 남기지 않는다.

### 교차형 배치 (2026-09-13 개정)

**전 장에 공통으로 적용되는 규칙은 하나다 — 이론과 실습을 분리하지 않는다.** 실습을 뒤에 몰아 두지 않고, 개념을 설명한 자리에서 바로 실행해 그 출력으로 개념을 확인한다. 실습 전용 절을 따로 두지 않는다.

**그 밖의 것은 장마다 다르게 정한다.** 실습 수, 절 개수, 실행 블록의 위치는 그 장의 실습 자산과 주제에 맞춘다. 아래는 기본형이며 장마다 어긋나도 된다.

- 개념 절 하나에 실행 블록 하나를 두는 것이 기본이다. 실행할 것이 없는 개념 절은 다른 장의 산출물을 인용하거나 실행 블록 없이 둔다.
- 실행 블록은 다음 네 요소를 갖춘다. 순서와 분량은 장에 맞게 조정한다.
  - **실행 명령** — `bash` 블록
  - **출력 발췌** — `text` 또는 `json` 블록. 첫 줄에 `# 출처: <산출물 경로>`를 적는다
  - **화면에 나온 값에서 읽을 것** — ○ 항목 몇 개
  - **주의** — `>` 인용 블록. 오해하기 쉬운 지점이 있을 때만
- 예측-대조 학습을 쓰는 장에서는 예측표를 첫 실행 블록보다 **앞 절**에 둔다. 모든 장에 둘 필요는 없다.

**다만 조정하는 것은 `lecture/chNN.md`의 실습 서술뿐이다.**

### 시작 전 준비 절

선행 조건이 `pip install` 하나로 끝나지 않는 장에는 실습 절 첫머리에 `### 시작 전 준비`를 둔다. 자동화 스크립트 한 줄과, 그 장에서 무엇이 왜 필요한지 두세 문장을 적는다.

```bash
python scripts/setup_practice.py {N}
```

이 스크립트는 Python·Java 버전, Docker 데몬, 포트, 선행 장의 산출물, 환경변수를 점검한 뒤 가상환경을 만들고 패키지를 설치한다. `--check`를 붙이면 점검만 하고 아무것도 바꾸지 않는다. 장별 선행 조건은 스크립트의 `CHAPTERS` 표에 적혀 있으므로, 실습 구성이 바뀌면 그 표도 함께 고친다.

선행 조건이 없는 장에는 이 절을 만들지 않는다. 어느 주차에 무엇이 필요한지는 `scripts/setup_practice.py`의 `CHAPTERS` 표가 정하며, 2026-09-13 기준으로 다음과 같다.

| 주차 | 선행 조건 |
|---:|---|
| 1 | 공공데이터포털 인증키(선택) |
| 4 | Docker 필수, `kafka-python`, 포트 2181·9092·29092 |
| 5 | Java 17, `pyspark` |
| 6 | POSIX 전용(Windows 네이티브 불가), 네트워크, `apache-airflow` |
| 7 | `feast`·`pandas`·`pyarrow` |
| 9 | `mlflow`·`scikit-learn`·`pandas`·`pyarrow` |
| 10 | Docker 선택, `fastapi`·`uvicorn`·`mlflow` 등 |
| 13 | Docker 필수, `mlflow`·`httpx` 등 |
| 14 | LLM API 키(선택). Docker는 필요 없다 |

이 표와 본문이 어긋나면 스크립트 쪽이 사실이다. 실습 구성이 바뀌면 스크립트의 `CHAPTERS`와 이 표를 함께 고친다.

- `practice/` 아래에서 **기존 JSON 산출물의 스키마와 값은 바꾸지 않는다.** 시험과 과제가 그 파일을 참조한다.
- 다만 교차형 배치를 위한 다음 두 가지는 허용한다(2026-09-13 개정).
  - 기존 실습 코드에 **stdout 출력을 추가**한다. 계산 로직과 산출물 스키마는 건드리지 않는다.
  - 개념 절에 붙일 **실습 코드를 신설**한다. 파일명은 `{장}-{순번}-{이름}.py`를 따르고 `practice/chapter{N}/code/`에 둔다.
- 신설한 실행 명령은 **선행 조건을 늘리지 않는 범위에서만** 만든다. 그 장에 없던 Docker·Kafka·외부 API 의존을 새로 만들지 않는다.
- 강의계획서의 주차별 실습 구성과 주제를 바꾸지 않는다.
- 시험이 참조하는 산출물의 설명은 자르지 않는다(`exam/`에서 먼저 확인한다).

## 원천 자료

- `practice/chapter{N}/`: 실제 실행 코드와 산출물 — **사실·수치의 유일한 원천**
- `강의계획서.md`: 주차 배정, 주제, 실습 환경
- 비공개 저장소의 `lecture/docs/chapter{N}.md`·`contents.md`·`exam/`: 집필 시 참조용

**`lecture/docs/`는 2026-09-13부터 이 저장소에 두지 않는다.** 학생이 받는 저장소에서 상세 원고를 뺐으므로 다음이 따라온다.

- 본문에서 `lecture/docs/chapter{N}.md`를 **경로로 가리키지 않는다.** 기존 장에 남아 있는 참조는 재작성할 때 걷어낸다.
- "더 알아보기"는 세 가지만 가리킨다 — ① `practice/chapter{N}/`의 확장 실습 ② 외부 원문 링크(3개 이하) ③ 뒤 장의 번호.
- 상세 원고에만 있고 실행 산출물에 없는 수치는 본문에 싣지 않는다. 학생이 확인할 경로가 없기 때문이다.

실행 산출물에 없는 사실·수치·실행 결과·법령 해석은 임의로 추가하지 않는다.

## 실행 증거와 수치 인용 (2026-09-13 신설)

**본문에 적은 수치는 전부 실행 산출물에서 옮긴 값이어야 하고, 어느 파일에서 옮겼는지 본문에 적는다.** 출처를 적을 수 없는 수치는 싣지 않는다.

증거는 두 등급이다. 장마다 가능한 쪽을 쓴다.

| 등급 | 증거 | 쓰는 경우 | 출처 표기 |
|---|---|---|---|
| A | `practice/chapter{N}/results/*.log` — stdout 전문 캡처 | Docker·외부 API 없이 지금 재실행되는 장 | `# 출처: practice/chapterN/results/X.log` |
| B | `practice/chapter{N}/data/output/*.json` — 과거 실행이 남긴 산출물 | Kafka·Spark·Airflow·Feast·Docker가 필요해 재실행할 수 없는 장 | `# 출처: practice/chapterN/data/output/X.json` |

- A등급을 만들 수 있으면 A를 쓴다. 재실행이 막히는 장은 B로 간다. B를 쓴 장은 본문 머리말에 "이 장의 수치는 과거 실행이 남긴 산출물에서 옮긴 값"이라고 적는다.
- **실행하지 않고 값을 쓰지 않는다.** 어느 등급에도 근거가 없으면 그 수치를 빼고 서술을 바꾼다.
- 다른 장의 산출물을 인용할 때도 같은 규칙을 적용한다. 장 번호와 파일 경로를 함께 적는다.
- 입력 자료에 없어 구성한 값(도착 시각, 지연 분포 등)이 있으면 **구성값임을 본문에 밝힌다.** 난수를 쓰지 않고 규칙을 코드에 고정한다.
- 각 장 머리에 한 줄을 둔다 — `> 이 장의 수치는 모두 practice/chapter{N}/의 코드를 실행해 얻은 값이다. 예시를 위해 지어낸 숫자는 없다.`

## 무엇을 남기고 무엇을 자르는가

자를 기준은 **난이도가 아니라 역할**이다. 어려워 보여도 이 과목의 뼈대인 개념은 남기고, 쉬워 보여도 실무자가 조직에서 쓰는 절차는 자른다.

| 판정 | 대상 | 예 |
|---|---|---|
| **반드시 남긴다** | 뒤 장에서 반복해 회수되는 개념 | 침묵 실패, 학습-서빙 불일치, 드리프트 |
| **반드시 남긴다** | 시험 출제 범위에 걸린 개념 | `exam/`에서 확인한 뒤 결정 |
| **반드시 남긴다** | 실습에서 손으로 확인하는 것 | 응답 JSON 구조, 결측 표기, 성공 코드 |
| **반드시 남긴다** | 이 개념이 없으면 발생하는 구체적 사고 | 결측 `"-"`를 0으로 바꿔 "대기질 좋음"이 되는 왜곡 |
| **자른다** | 등급·수준 카탈로그 | MLOps 성숙도 수준 0/1/2, 성숙도 자가 진단 |
| **자른다** | 법령 조문 번호와 예외 규정 | 개인정보 보호법 제18·23·33·37조의2 조문 대조 |
| **자른다** | 조직 운영 절차 | 발주 문장 작성, 검수 포인트, 예산·TCO 산정 |
| **자른다** | 용어 목록형 나열 | 기술 부채 3종 이름, 도구·프레임워크 이름 열거 |
| **자른다** | 민간↔공공 대조표와 "역방향" 절 | 실무교재의 비교 표 전체 |
| **자른다** | 출처·인용 자격 구분 서술 | "직접 선례/방법론 차용" 표기는 `docs/`에만 둔다 |

자른 내용은 없애는 것이 아니라 **"더 알아보기"에서 `practice/chapter{N}/`의 확장 실습, 외부 원문, 뒤 장의 번호로 가리킨다**. 학생이 실제로 열어볼 수 있는 경로만 적는다.

한 가지 예외: 자르면 **핵심 위험 자체가 사라지는 경우**에는 절차를 빼되 위험은 한 문장으로 남긴다. 예를 들어 법령 조문 목록은 자르되, "공공 AI가 사람 대신 결정하면 시민이 설명을 요구하고 이의를 제기할 수 있어야 한다(자세한 조문은 16장)"는 남긴다.

## 분량

- **장당 320줄 이하**(문단 서술 기준). 250-300줄이 표준이다.
- **코드 블록·출력 블록·표·인용 블록은 상한 계산에서 뺀다**(2026-09-13 개정). 교차형 배치에서 실행 블록이 차지하는 줄은 다루는 개념의 양과 무관하다. 서술 줄만 세어 320줄로 판정한다.
- 개조식 전환으로 늘어난 줄은 상한 계산에서 빼고 센다. 상한은 **다루는 개념의 양**을 재는 기준이지 줄 수 자체가 목적이 아니므로, 같은 내용을 □·○·–로 쪼개 늘어난 분량은 초과로 보지 않는다.
- 상한을 넘으면 내용을 더 넣지 말고 **개념 수를 줄인다**. 개념 4개가 300줄이면 개념 3개로 줄여 각각을 더 풀어 쓴다.
- 핵심 개념 1개당 40-70줄을 쓴다. 개념 하나가 20줄 미만이면 그 개념은 이 장에서 다루기에 이르거나, 애초에 핵심이 아니다.

## 서술 형식 — 개조식·계층형

비공개 저장소의 상세 원고는 문단 서술을 쓴다. `lecture/chNN.md`는 **반대로 개조식을 쓴다**(2026-08-30 사용자 지시). 학생이 화면을 훑으며 구조를 먼저 잡게 하는 것이 목적이다.

- 설명은 **계층형 개조식 항목**으로 쓴다. 여러 문장을 이어 붙인 서술 문단으로 쓰지 않는다.
- 계층 기호는 **□ → ○ → –** 세 단계로 고정한다. 마크다운 불릿(`-`) 뒤에 기호를 붙인다.
  - `- □ ...` — 절 안의 논점 하나
  - `  - ○ ...` — 그 논점의 갈래
  - `    - – ...` — 근거·예시·수치·단서
- 네 번째 단계로 더 들여쓰지 않는다. 더 나눠야 하면 □ 항목을 하나 더 만든다.
- 종결은 `~함`·`~임`·명사형으로 끝낸다. 정의문과 결론문은 뜻이 흐려지지 않게 `~이다`·`~한다`로 쓸 수 있다.
- 한 항목에 한 가지만 담는다. 두 가지를 말하고 있으면 항목을 나눈다.
- **표·그림·플로차트·코드 블록·인용 블록은 개조식으로 바꾸지 않는다.** 있는 형태 그대로 둔다.
- 표는 대조·분류처럼 표가 아니면 읽기 어려운 곳에만 쓴다. 설명용 표는 장당 2개 이하로 하되, 예측표와 실행 순서표는 이 수에 넣지 않는다.
- 코드는 화면에 보이는 것을 설명하는 데 필요한 3-5줄만 넣고, 전체 코드는 `practice/`를 가리킨다.
- 예외로 **실행 결과를 주석으로 붙인 코드 블록은 25줄까지** 쓸 수 있다(2026-09-13 개정). 장당 1회로 제한하고, 주석에 적는 출력은 산출물에 있는 값을 그대로 옮긴다. 나머지 절은 출력 발췌만 싣는다.
- 영어 음차 전문용어는 각 장 첫 등장 시 원어를 병기한다(프로젝트 CLAUDE.md 규칙).

## 장 템플릿

아래는 기본형이다. **장마다 절 구성이 달라도 된다** — 실습 자산과 주제가 장마다 다르기 때문이다. 어느 장에서도 어기지 않는 것은 3번 한 줄, 곧 개념 절 안에서 실행한다는 규칙뿐이다. 절 번호는 1부터 빠짐없이 이어 붙인다.

1. **오늘의 질문** — 3-4개. 이 장을 마치면 답할 수 있어야 하는 질문.
2. **이 장에서 실행할 것** — 비유 한 문단(장 전체를 관통하는 비유 1개, 왜곡 지점 한 줄), 예측표, 실행 순서표(파일·하는 일·대응 절·선행 조건). 실행하기 전에 채울 것을 여기서 채운다.
3. **핵심 개념 3-4개** — 개념마다 `왜 필요한가 → 무엇이 깨지는가(구체 상황) → 어떻게 막는가` 순서로 쓰고, 절 끝에 그 개념을 확인하는 실행 블록을 붙인다. 개념 하나가 절 하나다.
4. **핵심 요약** — 4-5개 항목. 핵심 개념 수와 맞춘다. 질문을 던지지 말고 **답을 확정해 준다**. 각 항목은 굵은 글씨의 결론 한 문장으로 시작하고, 두세 문장으로 근거를 붙이며, 끝에 근거가 나온 절 번호를 적는다.
5. **과제** — 1개. 제출처는 LMS, 기한은 수업일 포함 7일. 실행해 만든 산출물 파일과, 그 산출물의 값을 근거로 판단하는 서술을 함께 제출하게 한다.
6. **더 알아보기** — 이 장에서 자른 내용을 `practice/chapter{N}/`의 확장 실습, 외부 원문(3개 이하), 뒤 장의 번호로 가리킨다. 저장소에 없는 파일 경로는 적지 않는다.

**넣지 않는 절(전 장 공통)**: 활동·토론, 확장 과제(선택), 체크 질문, 실습 전용 절. 수업 밖에서 하는 일은 과제 하나로 모은다.

## 주차 배정과 파일 구조

파일명은 주차 번호를 붙인 `ch{주차}.md` 형식이다. 1주차 강의본은 `ch01.md`이고 12주차 강의본은 `ch12.md`다. 한 주에 상세 원고 두 장을 쓰더라도 주차용 강의본은 하나만 둔다. 상세 원고와 실습은 기존 장 번호를 유지하므로 본문에서 출처 경로를 명시한다.

| 주차 | 강의계획서 주제 | 파일 |
|---:|---|---|
| 1 | 데이터 엔지니어링과 MLOps | `ch01.md` |
| 2 | 공공 데이터 품질 | `ch02.md` |
| 3 | 파이프라인 아키텍처 | `ch03.md` |
| 4 | Kafka | `ch04.md` |
| 5 | 스트리밍 처리 | `ch05.md` |
| 6 | 배치 처리 | `ch06.md` |
| 7 | 피처 스토어 | `ch07.md` |
| 8 | 중간고사 | — |
| 9 | 실험과 모델 관리 | `ch09.md` |
| 10 | 모델 배포와 CI/CD | `ch10.md` |

4주차 `ch04.md`는 상세 원고 4·5장과 실습 `practice/chapter4`를 한 흐름으로 묶는다. 12주차 `ch12.md`는 상세 원고 13장을 중심으로 16장의 설명·이의제기 부분을 선별하며, 본 실습은 기말고사와 연결된 `practice/chapter12`를 사용한다.

**주차용 강의본에서 뺀 상세 장**: 상세 원고 12장(부하 테스트)과 17장(베스트 프랙티스)은 강의계획서에 배정하지 않았다. 두 장의 내용은 비공개 저장소에만 있으므로 강의자료에서 경로로 가리키지 않는다. `lecture/ch12.md`는 상세 12장이 아니라 12주차 강의본이다.

- `lecture/assets/ch{NN}/`: 강의용 그림·도식은 출처 장 번호를 유지한다

비공개 저장소의 상세 원고에 실린 그림·도식은 해당 내용이 강의자료에도 있으면 그대로 가져다 쓴다. 새로 그리지 않고 `lecture/assets/ch{NN}/`에 복사한 뒤 같은 그림 번호로 참조한다. 캡션은 학부 수준으로 다시 쓰되, 그림이 실측이 아니라 구성 시나리오면 그 사실을 캡션에 밝힌다.
- `lecture/slides/`: 필요 시 강의 슬라이드 초안
- `lecture/ch{NN}.pdf`: 같은 주차 번호의 마크다운에서 만든 배포용 PDF. 원고를 고치면 다시 만든다.

각 파일은 제목 바로 아래에 `> **N주차 · 주제**` 한 줄을 둔다.

## 금지 사항

- 실무교재에 없는 실행 결과를 "예시 결과"처럼 쓰지 않는다.
- 어려운 내용을 자르면서 핵심 위험까지 없애지 않는다. 절차는 자르되 위험은 한 문장으로 남긴다.
- 시험 출제 범위에 걸린 개념을 확인 없이 자르지 않는다.
- 비유를 위해 법·규제·보안 요구사항을 단순화해 단정하지 않는다.
- 비공개 저장소의 상세 원고와 다른 용어를 임의로 만들지 않는다.
- 이 저장소에 없는 파일 경로를 본문에 적지 않는다.
- 실무교재의 절 구성을 그대로 옮겨 놓고 각 절을 줄이는 방식으로 작성하지 않는다.

## 기존 장을 고칠지 판정하는 기준

**현재 원고가 아래 여섯 조건을 모두 만족하면 수정하지 않는다.** 규정이 바뀌었다는 이유만으로 멀지만 다시 쓰지 않는다.

1. 서술 줄이 320줄 이하인가(코드·출력·표·인용 블록은 빼고 센다).
2. 이론 부분의 핵심 개념이 4개 이하인가.
3. 삭제 대상 절(활동·토론, 관찰 과제, 확장 과제, 체크 질문, 실습 전용 절)이 없는가.
4. 자르기로 한 항목(성숙도 등급표, 법령 조문 목록, 발주·검수·예산, 민간↔공공 비교표, 역방향 절)이 본문에 없는가.
5. 설명이 □·○·– 세 단계의 계층 개조식인가.
6. 개념 절마다 실행 블록이 붙어 있는가. 이론에 설명이 없는 실습이 남아 있지 않은가.
7. 본문의 모든 수치에 산출물 경로가 붙어 있는가.

조건을 못 맞춘 항목만 고친다. 일곱 중 네 개 이상이 어긋나면 그때 장을 다시 쓴다.

**2026-09-13 개정 시점 기준으로 `ch01`~`ch14` 전부가 6·7번을 못 맞춘다.** 교차형 배치와 출처 표기는 이번 개정에서 새로 들어온 규정이므로, 각 장은 순서대로 재작성 대상이다.

## 작성 절차

1. 비공개 저장소의 `lecture/docs/chapter{N}.md`와 `contents.md`의 학습 목표를 읽는다.
2. `exam/midterm.md`·`exam/final.md`에서 해당 장이 걸린 문항을 확인한다.
3. 핵심 개념 3-4개를 고르고, 자를 항목을 위 판정 표로 분류한다.
4. 개념 순서대로 작성한다. 다 쓴 뒤 줄 수를 세어 상한을 확인한다.
5. 상한 초과 시 개념을 줄인다. 문장을 압축하지 않는다.
